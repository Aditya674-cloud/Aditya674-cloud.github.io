Autonomy development · active01 / ROBOTICS

Drone-ShadowClone — Autonomous UAV Navigation

A staged autonomy project using PX4 SITL, Gazebo Harmonic, ROS 2 Jazzy and Python. The first milestone completed a 5 m waypoint mission in simulation, with successful repeated runs and automatic landing. The next milestone adds a 2D LiDAR-equipped vehicle and a static obstacle in a custom Gazebo world.

Current technical progress: the LiDAR scan is bridged into ROS 2; a forward-sector detector identifies the closest valid return; a test publisher converts scan data into PX4 obstacle-distance format; and an independent Offboard response controller has been developed. The initial flight test achieved take-off and altitude hold, but stale LiDAR data prevented reliable forward motion. Full lateral avoidance and path replanning are therefore still incomplete.

Design iteration & CAE study02 / MECHANICAL

Self-Balancing Two-Wheeled Vehicle — Frame Design & FEA

A mechanical design study of a Segway-class self-balancing vehicle frame. The work progressed through successive CAD revisions to address rider loading, hub-motor mounting, stress concentration and packaging. The documented static study applies a 981 N load representing a 100 kg rider to compare frame iterations, with the optimized Version 4.2 presented here.

Analysis workflow: frame architecture and material selection (plain carbon steel, IS 2062 Grade E250 as recorded in the study), centre-of-gravity and stability calculations, an inverted-pendulum / Lagrangian mechanics model, static FEA, mesh-refinement study and modal analysis. The reported first natural-frequency estimate is 41.634 Hz. These are simulation and analytical results; physical fabrication and experimental validation are not claimed.

Conceptual analysis · documented03 / THERMAL SYSTEMS

Thermal Management of a Conceptual Space Data Centre

A conceptual study inspired by Starcloud-4, examining a server enclosure, conductive cooling path and external radiator panels. The proposed path is server enclosure → thermal interface / cooling tube → radiator panels → space. The model is a learning and design investigation, not a flight-qualified spacecraft thermal design.

Analytical baseline: 150 W server heat load, 0.48 m² total radiator area, emissivity 0.92 and a 3 K deep-space sink assumption. A Stefan–Boltzmann energy balance gives an idealized equilibrium radiator temperature of approximately 278.19 K. ANSYS work documents temperature and heat-flux fields and mesh-sensitivity exploration; the numerical model still needs tighter consistency checks across boundary conditions and mesh cases before strong quantitative conclusions are drawn.

05 / Research practice

How I approach an engineering question

A developing research workflow built around transparent assumptions, traceable calculations and evidence-led iteration.

01 · FORMULATE

Define the system and question

Translate a broad engineering problem into a bounded question, identify operating conditions and establish measurable objectives.

02 · MODEL

Build the analytical baseline

Use first-principles calculations, physical assumptions and literature context before relying on a simulation result.

03 · IMPLEMENT

Develop the computational model

Build CAD, FEA, thermal or robotics simulation models with explicit inputs, boundary conditions and software versions.

04 · TEST

Observe and challenge results

Compare iterations, inspect failure modes, check sensitivity and document unsuccessful tests rather than hiding them.

05 · REPORT

Communicate limitations

Separate calculated, simulated and experimentally validated outcomes. Record what remains uncertain and what should be tested next.
